# Записная книжка по MCP

Твой нетворк отвечает на вопросы других людей и не отдаёт ни имён, ни переписки.

Человек спрашивает своего Claude: «нужен венчурный инвестор в Дубае». Claude обращается к твоей книжке, и ответ такой:

```json
{
  "answer": "могу_познакомить",
  "understood": ["инвестор", "дубай"],
  "ref": "q_JiCC8xfRQOVC"
}
```

Дальше он может запросить интро, а ты решаешь, спрашивать ли контакта. Имя человек узнает, только когда согласились и ты, и контакт.

Раздатка к четвёртой встрече практикума [AI × Networking](https://hegai.net/p/ai-networking). Никакой общей базы тут нет: у каждого своя книжка на своём компьютере, а общий только протокол. Подключил пятерых, спрашиваешь пятерых.

## Как поставить

Нужны [Claude Code](https://claude.com/claude-code) и Node 20+. Ни `npm install`, ни базы, ни ключей.

```bash
git clone https://github.com/chemp1/hegai-network-mcp.git
cd hegai-network-mcp
npm run demo    # выдуманная книжка на 164 человека
npm test        # 32 проверки, в том числе что имена не утекают
claude
```

## Четыре ответа

| Ответ | Что значит |
|---|---|
| `могу_познакомить` | есть такой человек, и ты знаешь его лично |
| `есть_похожие` | совпало не всё или связь слабая, интро не обещано |
| `нужно_уточнить` | запрос общий или не распознан, сервер задаёт вопрос |
| `нет` | в этой книжке такого нет |

Ни числа людей, ни имён, ни компаний сервер не отдаёт. Витрина тегов показывает только округлённые значения, например «инвестор 100+», и только там, где людей не меньше пяти.

## Шаги

| Команда | Что делает |
|---|---|
| `/book-import` | собирает книжку из Личной CRM, LinkedIn и любого CSV |
| `/book-tag` | модель читает контекст и ставит теги |
| `/book-publish` | показывает витрину, запускает сервер, выдаёт токен гостю |
| `/intro-inbox` | твои входящие: кто просит интро и кто что спрашивал |
| `/ask-network` | сторона гостя: спросить все подключённые книжки |

## Как это устроено

```
приватное, у тебя                 то, что читает сервер
data/book.jsonl  ── build-index ─▶ data/index.jsonl   только теги и теплота
data/secret                        data/showcase.json витрина
                                   data/guests.json   хеши токенов
```

Сервер физически не открывает `book.jsonl`. Строка индекса выглядит так:

```json
{"k":"xV3f9qLm2Pz0aB1c","role":["инвестор"],"geo":["дубай"],"warmth":"warm"}
```

Ключ `k` непрозрачный: обратно в имя его переводит только `scripts/inbox.mjs` у тебя на машине. Гостю ключи не показываются.

## Приёмная: разговор вместо меток

С флагом `--desk` у книжки появляется инструмент `talk_to_owner`: агент участника говорит обычным языком, книжка спрашивает зачем и передаёт тебе карточку с черновиком вопроса контакту. Имён не видит ни модель, которая пишет гостю, ни та, что читает его текст. Устройство, включение и риски: [docs/desk.md](docs/desk.md).

## Что остаётся за тобой

Прочитай [ПРИВАТНОСТЬ.md](ПРИВАТНОСТЬ.md) до того, как открывать книжку. Коротко: «да» и «нет» тоже что-то выдают. Сервер это ограничивает, но не отменяет.

Отправки в репозитории нет by design. Ни один скрипт не пишет ни контакту, ни гостю.

Начинаешь с нуля: [КАК-НАЧАТЬ.md](КАК-НАЧАТЬ.md). Работа круглые сутки на сервере: [docs/24-7.md](docs/24-7.md).
