# Приёмная: книжка разговаривает

Четыре метки хорошо работают, когда гость знает, кого ищет. Приёмная нужна, когда запрос сложнее: «нужен топ-менеджер из Росатома». Агент участника приходит и говорит обычным языком, а книжка отвечает так же, спрашивает зачем и передаёт тебе готовую карточку.

```
Гость: Нужен топ-менеджер из Росатома.
Приёмная: С такими запросами можно помочь, но сначала нужно понять задачу. Зачем разговор, какой результат нужен и что интересного собеседнику?
Гость: Хотим показать пилот ИИ-поиска по документации, результат за две недели.
Приёмная: Есть контакты рядом с темой. Передал запрос, интро не обещаю.
```

Тебе приходит карточка: кто просит, зачем, кого можно спросить, что учесть из вашего общения и черновик вопроса контакту. Решаешь и пишешь ты. Если модель считает, что беспокоить человека не стоит, она скажет это тебе, но спрятать запрос не может.

## Почему три модели, а не одна

Один агент с именами, который читает чужой текст и отвечает наружу, рано или поздно всё выдаст. Поэтому контексты разделены:

| Модель | Что видит | Что отдаёт |
|---|---|---|
| Разбор | текст гостя, книжку не видит | поля запроса |
| Закулисье | должности кандидатов и контекст общения. Поля с именем нет, но в заметках и переписке имена встречаются | наружу один сигнал из трёх, остальное только тебе |
| Приёмная | только сигнал: ни книжки, ни реплики гостя | текст ответа |

Сверху стоит код: он сверяет исходящий текст с именами, никами и компаниями книжки и подменяет ответ готовой фразой, если нашёл совпадение. То, что назвал сам гость, не считается.

Приёмная не получает текст гостя не из вежливости. Иначе она повторила бы его слова, проверка подменила бы ответ заготовкой, и по этой разнице гость узнал бы состав книжки без цели и без лимита. Поэтому ответы немного шаблонные. Это цена, и мы её платим.

И главное правило: **пока гость не назвал понятную цель, книжка вообще не проверяется.** Ответ на «есть ли кто-то из Росатома» до этого момента одинаковый при любой книжке, потому что код туда не ходил. Каждая проверка стоит гостю названной цели, лежит в твоём журнале и ограничена пятью в сутки.

## Как включить

Нужна модель с OpenAI-совместимым API. Выжимки контекста общения уходят этому провайдеру, больше никуда: выбирай того, кому доверяешь эти тексты.

```bash
export NETWORK_LLM_BASE_URL=https://api.example.com/v1
export NETWORK_LLM_KEY=...
export NETWORK_LLM_MODEL=...
node scripts/server.mjs --desk
node scripts/guests.mjs add "Андрей" --url https://адрес/mcp --profile "Основатель edtech, участник heg.ai" --desk
```

Токен без `--desk` приёмную не откроет: она работает с приватной книжкой, и пускать в неё надо осознанно.

У гостя появляется инструмент `talk_to_owner`, а прямой `ask_network` в этом режиме пропадает. Входящие разбирает `/intro-inbox`: `node scripts/inbox.mjs show <ref>` покажет карточку.

## Демо-экран

Разговор, решения кода и карточка владельца на одном экране. На нём видны имена, поэтому сервер запускает его только с выдуманной книжкой (`"demo": true` в `policy.json`), по ключу и с отдельным флагом:

```bash
npm run demo   # только выдуманная книжка: на настоящей экран не запустится
echo '{"demo": true, "owner": "Я", "demo_guest_profile": "Основатель стартапа"}' > data/policy.json
NETWORK_DESK_UI_KEY=$(openssl rand -hex 16) node scripts/server.mjs --desk --desk-demo-ui
```

Открывай `http://127.0.0.1:8787/desk?k=КЛЮЧ`.

## Что остаётся риском

- Сервер в этом режиме открывает приватную книжку: она нужна закулисью и проверке текста. Базовый режим без `--desk` её не читает. Разделить процессы можно, но пока это один процесс.
- Заметки и переписка уходят провайдеру модели как есть, вместе с именами, которые в них встретились. Если это не подходит, не подключай `crm_dir` и оставь короткие заметки.
- Закулисье читает текст гостя вместе с контекстом общения. Наружу от него уходит только сигнал, но текст в твоей карточке гость может попытаться подкрутить. Читай карточку глазами.
- «Да» после названной цели всё ещё подтверждает, что кто-то есть. Лимит делает перебор дорогим, а не невозможным.
- Проверка текста ловит имена из книжки, но не описания вроде «ваш однокурсник». Поэтому модель, которая пишет гостю, этих данных и не получает.
