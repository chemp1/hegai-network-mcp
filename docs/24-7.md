# Чтобы книжка отвечала круглые сутки

Локальный вариант живёт, пока открыт ноутбук. Этого хватает для начала. Если запросы пошли, сервер можно вынести: в индексе нет имён, поэтому на сервере не окажется ни твоей переписки, ни книжки.

**Что копируется на сервер:** код репозитория и четыре файла: `index.jsonl`, `showcase.json`, `policy.json`, `guests.json`.

**Что не копируется никогда:** `book.jsonl`, `book-overrides.json`, `secret`, партии и ответы разметки.

Схема:

1. Дешёвый сервер, Node 20+, и `node scripts/server.mjs --data /opt/book` под systemd.
2. Снаружи nginx с TLS на `127.0.0.1:8787`. Или именованный туннель Cloudflare, если у тебя там есть домен.
3. На своём компьютере `node scripts/build-index.mjs`, потом `rsync` четырёх файлов на сервер. Сервер перечитает индекс сам.
4. Запросы забирай к себе: `rsync сервер:/opt/book/{inbox.jsonl,refs.jsonl,log.jsonl} data/`, разбирай `/intro-inbox`, а `decisions.jsonl` отправляй обратно.

Быстрый туннель для этого не годится: Cloudflare пишет, что quick tunnels предназначены для тестов и разработки, и адрес меняется при перезапуске.

Если у тебя уже есть своя CRM на Postgres, индекс можно собирать прямо из неё: сервер всё равно читает только `index.jsonl`.
